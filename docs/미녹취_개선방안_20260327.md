## P0: SILENT-RECORDING 대응 (3건 — Case 2, 3, 6)

### 현상
PENDING APPLIED 후 할당된 채널의 RTP 스트림이 해당 통화와 매칭되지 않음.
- Case 2, 3: FILE CLOSE 발생했으나 RTP:0,0 (무음 파일 생성)
- Case 6: rtp_start=0으로 FILE OPEN 자체 미발생

### 근본 원인
SSPP 패킷에서 RTP 주소가 등록되었으나 실제 RTP 패킷이 도착하지 않거나, 도착해도 채널과 매칭되지 않음. KT228796** (DID:9672) 경유 호에서 반복 발생 — 특정 라우팅 경로에서 RTP가 녹취 서버를 우회할 가능성.

### 개선 방안 (AirREC C++ 수정 필요)

1. **SILENT-RECORDING 감지 시 재시도 로직**
   - FILE CLOSE에서 RTP:0,0 감지 시 PENDING 상태를 초기화하고 대체 채널에서 재매칭 시도
   - 구현 위치: `RecordManager::OnFileClose()` 또는 동등 함수

2. **RTP 수신 타임아웃 모니터링**
   - PENDING APPLIED 후 5초 내 RTP 미수신 시 경고 + 대체 채널 탐색
   - rtp_start=0 지속 시 채널 해제 후 재할당

3. **네트워크 구간 점검 (운영)**
   - KT228796** (DID:9672) 번호 그룹의 RTP 경로가 녹취 서버를 경유하는지 확인
   - 필요 시 네트워크 라우팅 수정

## P1: SSPP Type 5 패킷 유실 대응 (1건 — Case 1)

### 현상
PBX 콜 전환 후 새 세그먼트에 대한 SSPP Type 5 패킷이 녹취 서버에 미도달. SMDR I:IN_END만 도착하고 IR/IA 시퀀스 누락 (PACKET_LOSS 경고).

### 근본 원인
PBX-녹취서버 간 UDP 패킷 유실 또는 PBX 콜 전환 시 SMDR 미전송.

### 개선 방안

1. **NO-TYPE5 폴백 녹취 로직 (AirREC 수정)**
   - SMDR I:IN_END에 IR/IA가 없는 경우(PACKET_LOSS), 후행적으로 활성 채널을 탐색하여 녹취 시도
   - 구현 난이도: 상 (SMDR 파서 + 채널 매칭 수정)

2. **SSPP 패킷 로스 모니터링 (운영)**
   - NO-TYPE5 경고 발생 빈도를 추적
   - PBX-녹취서버 간 UDP 유실률 측정 도구 적용

3. **PBX 설정 점검 (운영)**
   - 콜 전환 이벤트에서 SMDR/SSPP를 정상 발생시키는지 PBX 설정 확인

## P1: BYE 후 통화 재개 미대응 (1건 — Case 8)

### 현상
RTCP BYE 수신 → RTP-GRACE(10s) → 파일 종료. 그러나 실제 통화는 207초 더 계속됨. 결과: 275초 통화 중 68초만 녹취 (24.7%).

### 근본 원인
BYE-grace 타임아웃 이후 RTP가 재개되어도 녹취가 재시작되지 않음. 보류 해제, 전환 등으로 RTP 스트림이 재개되는 시나리오 미대응.

### 개선 방안

1. **BYE-grace 종료 후 재연결 감지 (AirREC 수정)**
   - BYE-grace 종료 후 동일 Key에 대한 새 SSPP/RTP 감지 시 자동으로 새 녹취 세션 시작
   - 구현 위치: BYE-grace 타이머 핸들러

2. **BYE-grace 타임아웃 차등 적용**
   - 장시간 통화(예: 60초 이상)는 BYE-grace를 30초로 연장
   - 짧은 통화는 기존 10초 유지

3. **부분 녹취 경고 (분석 도구 — 완료)**
   - SMDR Duration vs FILE CLOSE Time 비교, 70% 미만 시 `partial_recording` 분류
   - **이번 커밋에서 log_analyzer.py에 구현 완료**

## P2: 발신 호 녹취 미개시 (1건 — Case 4)

### 현상
발신 호(O:OUT_END)에서 SSPP OUT 감지되었으나 rtp_start=0 유지 → REC-CHECK 미트리거 → FILE OPEN 없음.

### 개선 방안
1. SSPP OUT 시 m_rtp_info=1이면 rtp_start 조건을 완화하여 녹취 개시
2. 국제번호(2900 prefix) 발신 호에 별도 녹취 트리거 조건 설정

## P2: 다중 세그먼트 DB 매칭 (1건 — Case 5)

### 현상
콜 전환으로 다중 세그먼트 발생 시, 첫 번째 세그먼트가 PENDING HisId를 소진하여 이후 세그먼트의 DB 매칭 불가. O:OUT_END 발신 세그먼트도 DB_UPDATE FAIL.

### 개선 방안
1. 동일 Key에 대해 새 IR/IA 도착 시 새 PENDING + 별도 HisId 할당
2. DB_UPDATE FAIL 시 caller/called 조합으로 rec_his 재검색 (retry)
3. 발신 세그먼트(O:OUT_END)의 DB 매칭에 정규화된 번호 포함
